# Spark Prompts — 完整可行方案

> 版本：1.0 · 目标：本地可预览、GitHub Pages 可分享、支持自定义域名  
> 参考灵感：[Banana Prompt Quicker Gallery](https://glidea.github.io/banana-prompt-quicker/#gallery)  
> 实现原则：**纯静态、零构建、零后端**，降低部署与维护成本

---

## 1. 目标与边界

### 1.1 要解决什么

| 需求 | 方案结论 |
|------|----------|
| AI 提示词展示与检索 | 卡片画廊 + 搜索 + 分类/类型筛选 |
| 一键使用 | 弹窗详情 + 复制到剪贴板 |
| 本地能打开 | `start.bat` / 双击 HTML / 内置 PS 服务器 |
| 将来 GitHub 分享 | GitHub Pages 根目录静态托管 |
| 自定义域名 | 仓库 `CNAME` + DNS |

### 1.2 明确不做（第一阶段）

- 不做登录、云端同步、后端 API（收藏仅用浏览器 `localStorage`）
- 不做 Chrome 扩展（参考站的扩展能力不在本项目范围）
- 不做构建工具链（无 React/Vue/Vite，便于任何人改 HTML/JS 就上线）

后续若需要，可在不推翻本方案的前提下叠加：`prompts.json` 远程拉取、评论区、投稿 Issue 模板等。

## 3. 技术架构

### 3.1 选型

| 层 | 选择 | 理由 |
|----|------|------|
| 页面 | 静态 HTML | Pages 原生支持，无构建 |
| 样式 | 原生 CSS + CSS 变量 | 深/浅色一键切换，体积小 |
| 逻辑 | 原生 JS（IIFE） | 无打包，`file://` 也可运行 |
| 数据 | `js/data.js` 注入全局变量 | 避免 `fetch` 在 `file://` 下跨域失败 |
| 配置 | `js/config.js` | 站点名、GitHub、域名说明集中改 |
| 持久化 | `localStorage` | 收藏/主题，无需服务器 |

### 3.2 目录与职责

```
spark-prompts/
├── index.html              # 页面骨架与 SEO
├── css/styles.css          # 视觉与布局
├── js/config.js            # 站点配置（品牌/链接）
├── js/data.js              # 提示词 + 分类 + 公告
├── js/app.js               # 搜索/筛选/弹窗/复制/主题
├── assets/favicon.svg
├── start.bat               # Windows 一键本地服务
├── 打开网页.bat             # 双击直接打开
├── tools/local-server.ps1  # 无 Python 时的回退服务器
├── CNAME.example           # 自定义域名模板
├── docs/完整方案.md         # 本文档
├── 本地使用说明.txt
└── README.md
```

### 3.3 数据模型（单条提示词）

```js
{
  id: "唯一英文 id",
  title: "标题",
  category: "须在 CATEGORIES 中",
  tags: ["标签"],
  type: "generate" | "edit",
  date: "YYYY-MM-DD",       // 「近一周」筛选
  cover: "CSS 渐变或图片 URL",
  emoji: "卡片图标",
  summary: "一句话摘要",
  prompt: "完整提示词正文"
}
```

**维护规则**

1. 新增：在 `PROMPT_DATA` 追加对象，必要时更新 `CATEGORIES`  
2. 下线：删除或注释该对象  
3. 公告：改 `ANNOUNCEMENTS`  
4. 品牌/GitHub：改 `js/config.js`（并刷新页面）

### 3.4 运行时数据流

```
config.js + data.js 加载
        ↓
app.js boot()
        ↓
state = { query, category, filter, favorites }
        ↓
getFiltered() → renderGrid()
        ↓
用户操作 → 更新 state → 重绘 / openModal / copy
```

## 4. 本地使用方案（已实现）

| 方式 | 操作 | 适用场景 |
|------|------|----------|
| A 推荐 | 双击 `start.bat` | 完整功能（含复制 API） |
| B 零依赖 | 双击 `打开网页.bat` 或 `index.html` | 无环境机器快速看 |
| C 命令行 | Python / `local-server.ps1` | 开发调试 |

`start.bat` 探测顺序：

1. 可用的 Python `http.server`（避开 Store 空壳）  
2. `py -3`  
3. Node `npx serve`  
4. PowerShell `tools/local-server.ps1`

默认地址：`http://127.0.0.1:8080/`（端口占用时 PS 方案会自动换端口）。

## 5. 上线与分享方案（GitHub Pages）

### 5.1 推荐仓库形态

- 方案 **A**（推荐）：仓库 `spark-prompts`，地址  
  `https://<用户名>.github.io/spark-prompts/`  
- 方案 **B**：用户主页仓 `<用户名>.github.io`，站点在根路径  
  `https://<用户名>.github.io/`

### 5.2 上线步骤

1. 新建公开仓库，把本目录文件推到 **默认分支根目录**（保证有 `index.html`）  
2. Settings → Pages → Source：`Deploy from a branch` → `main` / `/ (root)`  
3. 等待 1–3 分钟，用 Pages 给出的 URL 访问  
4. 将 `js/config.js` 里的 `githubUrl` 改成真实仓库地址  

### 5.3 自定义域名

1. 复制 `CNAME.example` → `CNAME`，写入如 `prompts.example.com`  
2. DNS：  
   - 子域名：CNAME → `<用户名>.github.io`  
   - 根域名：按 GitHub 文档配置 A 记录  
3. Pages 设置填写同一域名，开启 HTTPS  
4. 推送后等待证书生效  

### 5.4 持续更新内容

```
改 data.js → git commit → git push → Pages 自动更新
```

无需重新构建；CDN/浏览器缓存一般数分钟内刷新。

## 9. 风险与对策

| 风险 | 对策 |
|------|------|
| `file://` 复制失败 | 引导用 `start.bat` |
| Store 假 Python | `start.bat` 先探测 `import http.server`，失败回退 PS |
| Pages 子路径资源 404 | 一律相对路径 `css/` `js/`，不用绝对根路径 `/css` |
| 数据过大 | 分文件或 JSON + 懒加载（阶段 2） |
| 提示词版权 | 自写或标注来源；公开仓注意许可 |

---

## 10. 结论：为何这套方案可行

1. **技术简单**：三件套 + 双 JS 数据/逻辑，任何人可改。  
2. **本地闭环**：有/无 Python 都能预览。  
3. **分享闭环**：GitHub Pages 零成本 HTTPS，域名一步到位。  
4. **体验对齐参考站核心**：画廊、筛选、详情、复制；扩展能力可后续加。  
5. **可演进**：静态根基不绑死框架，阶段 2/3 可渐进增强。
